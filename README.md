### Фильтры аккаунтов как на FunPay

| Поле                          | Что можно выбрать                                                               |
| :---------------------------- | :------------------------------------------------------------------------------ |
| **Тип сделки**                | Все предложения, продажа или аренда                                             |
| **MMR**                       | Диапазон «от/до» и числовая сортировка по возрастанию или убыванию              |
| **Тип аккаунта**              | Для продажи: с рейтингом, под калибровку (TBD), без доступа к рейтинговым играм |
| **Порядочность и вежливость** | Независимые диапазоны значений                                                  |
| **Матчи и часы**              | Диапазон количества матчей; часы доступны для продаваемых аккаунтов с рейтингом |
| **Автовыдача**                | Только предложения с автоматической выдачей, по данным нового сборщика          |

Основные параметры доступны сразу под выбором периода; остальные открываются кнопкой «Фильтры». Активные параметры отображаются отдельными метками и сбрасываются по одному. Заголовок столбца **MMR** переключает направление сортировки.

MMR берётся из структурированного поля `solommr`, без догадок по описанию. Неизвестный MMR идёт в конце при обоих направлениях сортировки и исключается при заданном диапазоне. Для признака автовыдачи нужны снимки, собранные после обновления; старые снимки сохраняются без изменений.

## 🚀 Быстрый старт

Понадобятся **Node.js 22.13+** (рекомендуется **24 LTS**) и **pnpm 11.25.0**.

```sh
git clone --branch main https://github.com/ubica1/funpay-analyzer.git
cd funpay-analyzer

npm install -g pnpm@11.25.0
pnpm install --frozen-lockfile
pnpm build
pnpm start
```

Откройте **[127.0.0.1:3400](http://127.0.0.1:3400)**.

1. **Получите первый снимок.** Нажмите «Собрать сейчас»: приложение прочитает включённые категории.
2. **Выберите рынок.** Переключитесь на «Реальные данные», укажите категорию, период и параметры.
3. **Начните накапливать историю.** Откройте «Сбор данных», включите расписание и сохраните настройки.

По умолчанию включены аккаунты, буст MMR и калибровка. Автоматический сбор включается пользователем. До появления реальных снимков приложение открывает обозначенный демо-режим.

<details>
<summary><strong>Запуск на Windows</strong></summary>

После установки зависимостей и сборки запустите **[`start-local.cmd`](start-local.cmd)** двойным щелчком.

Файл проверяет версию Node.js и запускает сервер. При наличии установленного Codex runtime используется его Node.js, иначе — системный. Для остановки нажмите `Ctrl+C` в окне запуска.

## 🐳 На своём сервере

В репозитории подготовлены Dockerfile и Docker Compose: перезапуск контейнера, постоянный том SQLite и вход по паролю.

```sh
cp .env.example .env
```

Откройте `.env` и задайте **собственный длинный пароль** в `ANALYZER_PASSWORD`. Затем:

```sh
docker compose up -d --build
```

| Что настроено  | Поведение                                                                                               |
| :------------- | :------------------------------------------------------------------------------------------------------ |
| **Хранение**   | База остаётся в Docker-томе `market-data` при пересоздании контейнера.                                  |
| **Перезапуск** | Политика `unless-stopped` возвращает приложение после перезапуска Docker.                               |
| **Доступ**     | Порт `3400` привязан к `127.0.0.1` сервера. Логин по умолчанию — `admin`, пароль берётся из `.env`.     |
| **Расписание** | Хранится в базе и возобновляется после запуска приложения. Ближайший сбор — через настроенный интервал. |
| **Реплики**    | Одна: планировщик работает внутри процесса приложения.                                                  |

Для доступа со своего компьютера удобно использовать SSH-туннель:

```sh
ssh -L 3400:127.0.0.1:3400 user@server
```

После подключения откройте [127.0.0.1:3400](http://127.0.0.1:3400). Для доступа через домен используйте reverse proxy с HTTPS. HTTP Basic передавайте через HTTPS или SSH-туннель.

> **Проверка развёртывания:** приложение и production-сборка проверены локально. Docker-конфигурация подготовлена; запуск контейнера нужно проверить в целевом окружении.

### Настройки сбора

Настраиваются прямо в интерфейсе, без редактирования конфигурационных файлов.

| Параметр         | По умолчанию                   | Доступно                                  |
| :--------------- | :----------------------------- | :---------------------------------------- |
| Расписание       | Выключено                      | Включение и пауза                         |
| Интервал         | 1 час                          | 15 мин, 30 мин, 1, 2, 6, 12 или 24 часа   |
| Хранение истории | 30 дней                        | 7, 14, 30, 90, 180 или 365 дней           |
| Категории        | Аккаунты, буст MMR, калибровка | Включение разделов и добавление по ссылке |

Сервер должен работать постоянно, чтобы сборщик выполнял расписание. После прохода сборщика снимки старше выбранного срока удаляются.

## 🔍 Как читать аналитику

Market Lens сохраняет **снимки публичных объявлений**. Показатели описывают наблюдаемое предложение на рынке.

| Показатель              | Как считается                                                                                                                   |
| :---------------------- | :------------------------------------------------------------------------------------------------------------------------------ |
| **Сводка и таблица**    | Последний доступный снимок каждой выбранной категории внутри периода. Повторные наблюдения одного объявления не суммируются.    |
| **Медиана**             | Центральная цена отфильтрованных предложений. Меньше зависит от единичных аномально дорогих лотов, чем средняя.                 |
| **Квартили**            | P25 и P75 — границы центральной половины ценовой выборки.                                                                       |
| **Изменение за период** | Сравнение с последним доступным снимком в предыдущем периоде той же длины, с теми же фильтрами.                                 |
| **График**              | Последний снимок каждого дня отдельно по категориям; выбранные фильтры применяются и к нему.                                    |
| **Продавцы**            | Уникальные продавцы в последних снимках после фильтрации.                                                                       |
| **Покрытие**            | Число собранных уникальных объявлений относительно счётчика категории FunPay. При неизвестном счётчике покрытие не вычисляется. |
| **CSV**                 | Вся текущая отфильтрованная выборка из последних снимков, независимо от страницы таблицы.                                       |

**Время:** Москва, UTC+3. Дни без наблюдений остаются пустыми. Для сопоставления цен выбирайте однородные товары и единицы услуги: общая медиана нескольких категорий может смешивать разные продукты.

### Границы данных

- **История начинается с первого сбора.** Прошлые месяцы автоматически не восстанавливаются.
- **Выборка может быть неполной.** FunPay ограничивает число объявлений в ответе. Покрытие показывается по исходному снимку и не меняется при применении фильтров. Показатели не экстраполируются на весь рынок.
- **Публичный каталог показывает признаки вероятных продаж.** Исчезновение лота может означать продажу, удаление или скрытие. В отчёте суммируются последние наблюдаемые цены лотов.
- **Отзывы относятся ко всему профилю продавца.** Онлайн-статус зафиксирован при сборе.
- **Избранное и сохранённые виды привязаны к браузеру.** Они хранятся в localStorage; фильтр избранного действует на текущей странице таблицы.
- **Демо изолировано.** Синтетические данные находятся в памяти и не записываются в рабочую SQLite-базу.

<details>
<summary><strong>Поведение сборщика при ошибках</strong></summary>

Запрос HTML ограничен 20 секундами и 20 МБ. При временном сетевом сбое или ответе 5xx выполняется повтор. Между категориями одной площадки выдерживается пауза. Браузерные сборщики и разбор большого каталога FunPay выполняются по очереди. Кнопка «Собрать сейчас» собирает только выбранную площадку/рынок и категорию. Проверка исчезнувших лотов FunPay выполняется отдельно в фоне: до 20 лотов за партию с бюджетом 30 секунд (текущий запрос может завершаться ещё до 8 секунд). Сборщик читает публичные объявления в рублях без авторизации и обхода защиты.

При CAPTCHA, ошибке HTTP, другой валюте или пустом разборе новый снимок не создаётся. Последний успешный снимок остаётся доступным с датой сбора, а ошибка появляется в журнале. После HTTP 403/429 следующая попытка выполняется по расписанию.

Разметка FunPay может измениться. Парсер изолирован в `server/collector.mjs`, поэтому его можно обновить независимо от интерфейса и расчётов.

</details>

## 💾 Данные и обслуживание

SQLite работает в режиме WAL. Снимок и объявления сохраняются одной транзакцией; повторяющиеся ID лотов удаляются из выборки.

Размер базы зависит от количества категорий, числа предложений, частоты сбора и срока хранения. Например, 3 категории × 3 000 лотов × 24 снимка × 30 дней дают около **6,5 млн наблюдений**. Увеличивайте интервал или сокращайте срок хранения, если нужно уменьшить объём истории.

Для резервной копии остановите приложение, сохраните **весь каталог базы или Docker-том** (включая WAL-файлы, если они есть), затем запустите приложение снова. Удаление тома `market-data` удаляет историю.

После удаления старых снимков SQLite переиспользует освободившееся место. Для физического уменьшения файла базы остановите приложение и выполните `VACUUM`, обеспечив запас свободного места.

```text
├── docs/images/          Превью продукта
├── compose.yaml          Постоянный серверный запуск
└── start-local.cmd       Запуск на Windows
```

**Проверено для этой версии:** production-сборка, 22 автоматических теста и пробный сбор публичных страниц FunPay. Тесты покрывают статистику, фильтры, границы дат, атомарность снимков, повторы лотов, парсер, CSV, HTTP API и доступ по паролю.

## Несколько площадок

Справа можно выбрать FunPay, GGSel, Playerok, Plati, Eldorado.gg, G2G, Z2U и PlayerAuctions,
а также «Общий рынок РФ» и «Остальной рынок».
На небольшом экране переключатель располагается над аналитикой.

Новые площадки содержат только **аккаунты Dota 2**. Категории FunPay сохранены.
Сводные режимы объединяют последние снимки каждой площадки по выбранной
категории. РФ (FunPay, GGSel, Playerok, Plati) считается в **RUB**,
зарубежный рынок — в **USD**. Валюты не конвертируются и не смешиваются.
Экспорт содержит площадку и валюту. Одинаковые названия продавцов разных
площадок не объединяются. Общая выборка может содержать один и тот же аккаунт,
выставленный на нескольких площадках: идентичность товара между ними не проверяется.

Проверка публичных страниц при разработке:

| Площадка | Автоматический сбор |
| --- | --- |
| FunPay | Существующий сборщик сохранён |
| GGSel | Индивидуальные объявления из JSON-LD каталога аккаунтов |
| G2G | Карточки публичного каталога, только цены USD |
| Z2U | Карточки публичного каталога, только цены USD |
| Plati | Карточки каталога Dota 2, отбор аккаунтов по названию; предметы и подписки исключаются |
| Playerok | Публичный каталог с пагинацией и точные параметры объявлений; ограниченная частота запросов |
| PlayerAuctions | Весь каталог аккаунтов Dota 2 через браузер, все страницы, цены USD; число лотов сверяется со счётчиком площадки |
| Eldorado.gg | Первая страница публичного каталога с ценами в USD. Браузер используется как резервный способ сбора |

В «Сборе данных» также доступна загрузка готового снимка площадки.
Поддерживается JSON до 5 МБ и 10 000 объявлений. Загружайте только аккаунты Dota 2:
содержимое импортированного файла по игре и типу товара не проверяется.
Снимок датируется моментом импорта; прошлые даты импортом не восстанавливаются.
Пример структуры (URL объявления замените действительным):

```json
{
  "platform": "eldorado",
  "currency": "USD",
  "offers": [{
    "url": "https://www.eldorado.gg/account/example",
    "title": "Dota 2 account",
    "price": 25,
    "seller": "Seller",
    "sellerId": "seller-1",
    "reviews": 0,
    "online": false,
    "attributes": { "solommr": "3000", "type1": "продажа" }
  }]
}
```

`platform`: `ggsel`, `playerok`, `plati`, `eldorado`, `g2g`,
`z2u`, `playerauctions`. `attributes`, `reviews`, `online` необязательны.
Параметры аккаунта (MMR, порядочность и т. п.) на новых площадках берутся из структурированных свойств или явно подписанных значений заголовка (`2529 MMR`, `Behavior 8763`). Диапазоны и значения с плюсом сохраняются как границы, а не как точные числа. Конфликтующие значения остаются неизвестными. Структурированные свойства имеют приоритет. Источник разбора отмечается в параметрах лота. Ранее сохранённые снимки новых площадок дополняются при запуске, без нового сбора. Для FunPay сохраняется разбор только структурированных полей. Интерфейс показывает число объявлений с известным MMR и отключает фильтры/сортировки без данных в выбранных снимках.
При неизвестных отзывах/онлайн-статусе используются 0/false; положительные
фильтры по этим полям исключают такие объявления. Неуказанные продавцы не
входят в счётчик уникальных продавцов.

Playerok получает страницы публичного каталога сразу с параметрами аккаунтов (без данных покупателя и реквизитов аккаунта и без запроса каждой карточки отдельно). Фильтр «С рейтингом» использует поле «Доступен рейтинг», MMR — поле `mmr`. Частота запросов ограничена, ответы 429 учитывают Retry-After. Прогресс отображает число обработанных аккаунтов. Снимок сохраняется после завершения сбора; при ошибке частичная выборка не заменяет предыдущую. Остальные сборщики читают одну публичную страницу без обхода защиты;
покрытие новых площадок неизвестно. Ошибка, другой формат валюты или отсутствие
объявлений не создают пустой снимок: последняя успешная выборка сохраняется.
На FunPay учитываются проверенные удаления лотов и замены аккаунтов. На других площадках вероятная продажа появляется после двух последовательных полных снимков без лота. Исчезновения из ограниченной выборки доступны отдельным списком и исключены из сумм вероятных продаж. При повторном появлении лота запись о выбытии снимается. Демо содержит отдельную синтетическую
историю для всех площадок и не записывается в рабочую базу.

Для старой базы столбцы площадки и типа категории добавляются автоматически;
существующие категории и снимки остаются привязаны к FunPay.

### Браузерный автосбор

На macOS и Windows требуется установленный Chrome. Можно указать
`BROWSER_EXECUTABLE_PATH` для другого установленного Chromium. На Linux выполните
`pnpm exec playwright-core install --with-deps chromium`. Dockerfile устанавливает
Chromium при сборке образа. Работа Docker в этой версии отдельно не проверялась.

Название объявления и стрелка ↗ в таблице открывают оригинальный URL с площадки
в новой вкладке; GGSel открывается в текущей вкладке. История цены вынесена в отдельную кнопку с часами. В демо
прямых ссылок на вымышленные объявления нет.

Над аналитикой показывается дата сохранённых данных. Ошибка сбора не считается
обновлением: выводится причина, а предыдущий успешный снимок остаётся доступным.
Если свежий снимок не входит в выбранный исторический период, интерфейс предлагает
расширить период. После ручного сбора отображается итог по категориям.

Фильтры новых площадок учитывают явно указанные диапазоны и нижние границы с плюсом. Нижняя граница применяется к фильтру «от», верхняя — к «до»; неизвестная верхняя граница не выдаётся за точное значение. Ссылки GGSel открываются в текущей вкладке, без всплывающего окна.

Фильтр «С рейтингом» означает открытый доступ к рейтинговым матчам. Для внешних площадок нужны явные признаки доступа (например, Rank Ready или «ОТКРЫТЫЙ РЕЙТИНГ»); MMR и медаль сами по себе не подтверждают доступ. Закрытый и неизвестный доступ исключаются. Для FunPay используются его структурированные поля.

Для G2G доступ к рейтингу дополнительно берётся из структурированного поля Rank в SSR-данных каталога: Rank Ready и конкретные ранги подтверждают открытый доступ. Заголовок TBD не отменяет этот признак; UnRanked без дополнительных данных не считается подтверждением доступа. JavaScript страницы при разборе не исполняется.

При открытии анализатора и переключении площадок выбраны «Продажа» и «С рейтингом». В таблице вероятных продаж у каждого лота отображается площадка.

### PlayerAuctions: браузерный сбор без API

Сборщик открывает публичный каталог https://www.playerauctions.com/dota-2-account/ и последовательно читает все страницы. Страница `/immortal/` является поиском по слову Immortal и не охватывает остальные аккаунты. В снимок попадают все объявления каталога независимо от фильтров интерфейса. Число уникальных лотов должно совпасть со счётчиком площадки: повтор страницы, изменение счётчика и недостающие объявления завершают сбор ошибкой, сохраняя предыдущий успешный снимок.

У каждого объявления сохраняется оригинальная ссылка, цена USD и продавец из его карточки. Описания читаются отдельно для уточнения MMR и доступа к рейтингу. Описания читаются последовательно после закрытия вкладки каталога, чтобы не перегружать VPS с 1 ГБ памяти. На уточнение отводится до пяти минут; три ошибки подряд останавливают этот этап. Недоступные и отложенные описания не удаляют лоты из полного снимка: параметры из карточек сохраняются, неизвестные значения не считаются подтверждёнными. Число неуточнённых описаний явно указывается в журнале сбора. Фильтр «С рейтингом» требует явного Rank Ready, Calibrated либо текущего ранга в описании; медаль с пометкой Expired не подтверждает доступ. Закрытый рейтинг исключается даже при наличии медали или MMR.

На Linux нужны Chromium (`pnpm exec playwright-core install --with-deps chromium`) и Xvfb (`apt install xvfb`). Анонимный профиль хранится рядом с базой в `browsers/playerauctions`. Системный браузер и его личные данные не используются. Для отдельного сетевого маршрута сборщика задаётся `PLAYERAUCTIONS_PROXY_URL=socks5://127.0.0.1:40000`. Прокси не меняет подключения других площадок. API-ключи не нужны. Если площадка требует ручную проверку браузера, сбор останавливается с ошибкой; автоматического решения CAPTCHA нет.
